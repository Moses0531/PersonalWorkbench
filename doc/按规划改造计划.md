# 按《功能模块规划》改造计划

> 对照文档：`doc/功能模块规划.md`  
> 对照范围：当前仓库前后端实现（`vue-module` / `springboot-module`）及 SQL 种子  
> 目标：从「个人工作台」演进为「面向小型团队的项目协作平台」

---

## 1. 总览对照

| 规划模块 | 现状 | 动作 |
|---------|------|------|
| 系统管理 | 已有（用户 / 角色 / 权限 / 菜单） | 保留，按需扩展菜单项 |
| 操作日志 | 无 | **新建** |
| 注册登录 | 已有 | 保留 |
| 个人信息 | 已有 | 保留 |
| 组队招募 | 无 | **新建** |
| 团队管理 | 无 | **新建** |
| 项目管理 | 个人「事务树」根节点，非团队项目 | **改造** |
| 任务协作 | 个人任务树 + 看板状态 | **改造** |
| 即时通讯 | 无 | **新建** |
| AI 摘要 | 无 | **新建** |
| AI 复盘总结 | 无 | **新建** |
| AI 桌面助手对话 | 有，规划未单列 | **保留**（见 §3.1） |
| AI 智能规划 | 有，规划未单列 | **暂留**，上线可关权限（见 §3.2） |
| 会议 / 笔记 / 日程 | 规划外；工作区已删代码 | **落盘清理残留** |

当前产品仍是个人工作台；规划目标是团队协作平台。核心差距：组织（团队 / 招募）、协作上下文（项目归属团队）、沟通（频道）、规划内 AI（摘要 / 复盘）。

## 2. 按规划：缺少什么

### 2.1 操作日志模块（全缺）

规划要求：关键操作留痕、按条件查询。

建议交付：

- 表：`sys_operation_log`（操作人、模块、动作、IP、时间、详情等）
- 后端：AOP / 拦截器写入 + 分页查询 API
- 前端：管理端「操作日志」页
- 权限：在 `sys_permission` 增加菜单与按钮权限

### 2.2 组队招募模块（全缺）

规划要求：招募发布、浏览筛选、加入申请、发起人确认后组建团队。

建议交付：

- 表：`recruit`、`recruit_application`（技能标签、人数缺口、赛事截止、状态；申请与审核）
- API + 页面：发布 / 列表筛选 / 申请 / 确认
- 与「团队管理」打通：确认通过后创建或加入团队

### 2.3 团队管理模块（全缺）

规划要求：团队创建与维护、成员管理、团队内角色、邀请码加入。

建议交付：

- 表：`team`、`team_member`；邀请码字段或 `team_invite`
- API + 页面：创建、改信息、成员增删、角色分配、凭码加入
- 作为后续项目 / 任务 / 频道的组织边界

### 2.4 项目管理模块（半有 → 需改造）

**已有（可复用）：**

- `task.nodeType = project` 作为容器节点
- 附件上传 / 下载 / 资料状态（OSS）

**相对规划仍缺：**

- 项目归属 **团队**（现为 `userId` 个人维度）
- 独立项目域：列表、项目工作区入口（而非仅嵌在「事务」树）
- 项目网盘：按项目权限控制访问、多版本、资料状态完善
- 工作区统一入口：任务协作 + 文档共享 + 频道

### 2.5 任务协作模块（半有 → 需改造）

**已有：**

- 任务 CRUD、父子树、看板 `status`、截止时间字段
- 首页 Dashboard 对个人待办的聚合展示

**相对规划仍缺：**

- 任务指派给团队成员（负责人）
- 任务下讨论 / 评论
- 临近截止自动提醒
- **团队概况**（当前 Dashboard 仅个人）
- 与「频道讨论 → AI 摘要确认 → 落任务」闭环衔接

### 2.6 即时通讯模块（全缺）

规划要求：项目频道文本消息、@提醒、引用任务与文件。

建议交付：

- 消息表 + 与项目绑定的频道模型
- 实时通道（WebSocket / SSE 等）
- 前端项目内频道页；支持 @ 与内容引用

### 2.7 AI 摘要模块（全缺）

规划要求：

- 复用三类内容：项目频道讨论、任务讨论、项目文档
- 讨论摘要固定四要素：结论、待办、负责人、截止
- 人工编辑确认后可转化为任务；不做自动全量分析

建议交付：在现有 `ai-module` 上新增摘要 API / Service；前端在频道、任务、文档处提供「生成摘要 → 编辑确认 → 转任务」。

### 2.8 AI 复盘总结模块（全缺）

规划要求：项目收尾手动触发；基于任务完成情况、频道记录、项目文档；总结成果 / 问题 / 经验；编辑确认后留档。

建议交付：复盘生成 API + 编辑留档；结果可作为项目资料归档。

## 3. 规划外能力：保留 / 暂留 / 删除

### 3.1 AI 桌面助手对话 — 保留

规划未将「通用 AI 对话」列为上线功能，但**代码与界面予以保留**，用途如下：

- 开发期：用对话界面联调与验证后续 AI 能力（摘要、复盘、以及可能的工具调用）
- 上线后：不删代码；在权限体系中关闭入口即可  
  - 权限标识：`ai:chat`（种子菜单「桌面助手」，`sys_permission` id 约 255）  
  - 从对应用户角色解绑，或将菜单权限停用，Dock / 命令面板不再下发该入口

相关现状（保留，勿按「多余模块」删除）：

- 后端：`AiController` 对话相关接口、`AIChatService`、会话 Redis 等
- 前端：`AiChatPage.vue`、`AiApi.js` 对话与会话接口

### 3.2 AI 智能规划 — 暂留

规划正式路径是「摘要四要素确认后转任务」，而非「目标拆解智能规划落板」。当前 `AiPlanService`、任务页规划弹窗、`planBatchId`、权限 `ai:plan` **暂保留**，便于与对话一起做 AI 联调；产品上线后同样可通过关闭 `ai:plan` 权限隐藏。

后续若摘要转任务能力稳定，可再评估是否下线智能规划，避免两套「AI → 任务」入口并存。

### 3.3 会议 / 笔记 / 日程 — 删除（规划外）

工作区已对 Meeting / Note / Event 及相关 AI 服务、前端页与 API 做删除标记。需完成：

- 确认删除落盘并清理半删状态
- 检查路由 / `pageComponents`、文档、SQL 种子中的残留菜单与表
- `DashboardPage` 等若仍引用会议 / 笔记 / 日程，一并去掉

### 3.4 杂项清理

| 项 | 建议 |
|----|------|
| `vue-module/src/stores/counter.js` | 脚手架示例，未使用，删除 |
| `deploy/`、Docker 相关 | 已删；与功能规划无关，可不恢复 |
| SQL 中独立 `project` 表 | 与现行 `task` 树不一致；改造「团队项目」时重建，勿沿用旧个人 `project` 语义 |

### 3.5 建议保留的非规划点名能力

| 项 | 说明 |
|----|------|
| Dashboard 首页 | 改造成「个人任务聚合 + 团队概况」入口，不删 |
| 验证码、OSS、动态菜单、RBAC | 基建，支撑规划模块 |

## 4. 建议实施阶段

```
阶段 0  清理规划外业务残留
        · 落盘删除 Meeting / Note / Event 及文档、菜单残留
        · 删除 counter store 等死代码
        · AI 对话、AI 智能规划：保留代码；确认权限可单独开关

阶段 1  组织底座
        · 团队管理 → 组队招募（依赖团队）
        · 操作日志（可并行）

阶段 2  协作容器
        · 项目从「个人 task 根」改为「团队项目」
        · 项目工作区 + 网盘（权限 / 版本 / 状态）
        · 任务：指派、讨论、提醒；Dashboard 团队概况

阶段 3  沟通
        · 项目频道 IM（消息、@、引用）

阶段 4  规划内 AI（优先在对话界面验证）
        · AI 摘要（频道 / 任务 / 文档 + 四要素转任务）
        · AI 复盘总结
        · 上线前：按角色关闭 ai:chat（及视需要关闭 ai:plan）
```

## 5. 已有可复用 vs 必须新建 / 大改

| 能力 | 复用 | 新建 / 大改 |
|------|------|-------------|
| 登录注册、个人资料 | 直接用 | — |
| 用户 / 角色 / 权限 / 菜单 | 直接用；增加新菜单与权限点 | 操作日志等管理端页 |
| 任务 CRUD + 看板列 | 作任务协作基础 | 团队 / 项目归属、指派、评论、提醒 |
| 附件 OSS | 作网盘起点 | 版本、项目权限、工作区 |
| AI 模块工程与对话界面 | 调 LLM、联调入口 | 新增摘要 / 复盘 API；对话上线靠权限关闭 |
| 个人 project 树模型 | 概念可参考 | 数据模型改为团队项目 |

## 6. 上线权限开关约定

| 权限 | 开发 / 联调 | 正式上线（首版） |
|------|-------------|------------------|
| `ai:chat` | 赋给开发 / 测试角色，用于验证后续 AI | 从正式用户角色移除或停用菜单，隐藏「桌面助手」 |
| `ai:plan` | 可保留便于联调 | 建议关闭；待摘要转任务稳定后再定是否保留 |
| 规划内模块权限 | 按模块逐步加菜单 | 按发布范围赋权 |

说明：关闭权限即可，**不必删除** AI 对话相关代码，便于后续迭代继续用作内部验证入口。

---

## 7. 结论

1. **按规划补齐**：操作日志、组队招募、团队管理、团队化项目与任务、即时通讯、AI 摘要、AI 复盘。  
2. **规划外业务删除**：会议 / 笔记 / 日程及残留引用。  
3. **AI 对话保留**：作为后续 AI 功能的验证界面；上线通过关闭 `ai:chat` 权限隐藏入口。  
4. **Dashboard 保留并改含义**，作为个人聚合与团队概况入口。
